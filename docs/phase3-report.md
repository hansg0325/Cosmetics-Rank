# Phase 3: 랭킹 내보내기

브라우저에서 실제 수집 버튼으로 100개 저장 완료, CSV/XLSX 다운로드, CSV 100행과 순위 확인, 빈 검색 결과에서 다운로드 버튼 비활성화를 검증했습니다. 별도 내보내기 메뉴에서도 날짜별 랭킹과 다운로드를 제공합니다.

랭킹 및 분석 화면에서 현재 날짜·카테고리의 검색·변동 필터가 적용된 표를 CSV 또는 XLSX로 저장합니다. 분석 화면에서 이탈 필터를 선택하면 이탈 상품도 포함됩니다. 순위 변동 차트 내보내기는 포함하지 않습니다.

날짜, 랭킹 카테고리 코드, 비교 기준일, 현재·이전 순위, 등락, 변동 상태, 상품 ID, 브랜드, 상품 대분류, 상품명, URL을 저장합니다. 가격·이미지는 포함하지 않습니다. CSV는 UTF-8 BOM과 수식 문자열 이스케이프를 사용하며 XLSX는 상품 ID를 문자열로 유지합니다. 빈 결과에서는 버튼을 비활성화합니다. ExcelJS는 버튼을 누를 때 지연 로딩합니다.

새 PC의 실제 수집 검증 과정에서 Python 서비스가 상품 대분류 필드를 거부하는 기존 문제를 발견했습니다. 선택 필드 `product_category`를 문자열 최대 100자로 검증하고 허용하도록 수정했습니다. 가격·이미지 등 다른 추가 필드는 계속 거부합니다.

검증: TypeScript 검사와 프로덕션 빌드, ESLint, Vitest 78개, Python 서비스 11개, 로컬 HTTP smoke(인증 및 샘플 2일 200행)가 통과했습니다. CSV 특수문자와 XLSX 재읽기 검증을 포함합니다. ExcelJS 청크 크기 경고는 남아 있습니다.

다음 단계는 실제 여러 날짜의 기록 축적과 비교 검증입니다. 기존 PC의 로컬 DB는 Git에 포함되지 않으므로 새 PC로 자동 이전되지 않습니다. 원격 배포와 원격 수집은 별도 작업입니다.
