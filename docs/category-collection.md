# 전체 및 카테고리별 랭킹 수집

대시보드에서 수집 카테고리를 선택하고 **지금 수집하고 저장**을 누릅니다. **전체 카테고리 취합**은 다음 10개 랭킹을 순서대로 수집하고 날짜·카테고리별로 각각 저장합니다.

전체, 스킨케어, 마스크팩, 클렌징, 선케어, 메이크업, 더모 코스메틱, 헤어케어, 바디케어, 맨즈에딧.

각 카테고리는 전체 상품의 분류를 필터링하는 대신 실제 해당 랭킹 탭의 1~100위를 읽습니다. 선택 탭과 최종 URL의 카테고리 파라미터가 일치해야 하며, 중복 없는 순위·상품 ID 100개를 검증합니다. Python과 TypeScript는 `src/shared/collectionCategories.json`의 고정 URL과 카테고리 목록을 공유합니다.

취합 동안 앱 화면을 열어두세요. 한 카테고리 수집·저장이 끝난 다음 다음 카테고리를 시작합니다. 실패한 카테고리는 최종 메시지에 이름과 오류를 표시하고 다음 카테고리를 진행합니다. 수집에 실패한 카테고리의 기존 완료 기록과 먼저 저장한 다른 카테고리는 유지됩니다. 저장 완료에 실패하면 성공으로 집계하지 않습니다. 같은 내용은 기존 스냅샷을 재사용합니다.

서버 코드는 Hono의 인증된 수집 API, Python 로컬 서비스와 D1 가져오기 API에 연결되어 있습니다. Chrome 실행은 로컬 PC에서 수행합니다. 원격 Workers 배포와 예약 실행은 추가하지 않았습니다.

## 실행

Git Bash에서 프로젝트 폴더로 이동해 `bash ./start-local.sh`를 실행합니다. 이미 실행 중이면 Ctrl+C로 종료한 뒤 다시 시작하고 브라우저를 새로고침하세요. 기존 로그인 토큰은 그대로 사용합니다. Python 서비스는 시작할 때 카테고리 설정을 읽으므로 서버 재시작이 필요합니다.

랭킹·분석·상품 이력·순위 변동·내보내기에서 수집한 카테고리를 선택할 수 있습니다. 가격·이미지는 수집하지 않습니다.

## 자동 검증

TypeScript 검사와 프로덕션 빌드, ESLint 통과. Vitest 80개, Python 서비스 15개 통과. 전체 10개 카테고리 API 요청과 출처 검증을 포함합니다.

## 실제 검증 결과 (2026-11-04)

브라우저에서 **전체 카테고리 취합**을 눌러 전체+9개 카테고리 모두 각 100개, 합계 1,000행을 처리했습니다. 성공 10개, 실패 0개, 약 153초였습니다. 1,000행 전체의 순위·상품 ID·브랜드·상품명·URL·상품 대분류를 해당 수집 결과와 D1 조회 결과에서 대조해 모두 일치했습니다. 가격 필드는 모두 NULL입니다.

캡처는 `data/all-category-captures.json`, 대조 결과는 `data/all-category-verification.json`에 저장했으며 Git에서 제외됩니다. 검증 앱은 포트 8791을 사용했고 기본 앱과 같은 로컬 DB에 저장했습니다. 기존 사용자 앱 프로세스는 종료하지 않았습니다.
