# 스킨케어 랭킹 수집 테스트

이 문서는 스킨케어를 먼저 검증한 시점의 기록입니다. 현재는 전체와 9개 카테고리를 지원합니다. [최신 사용법](category-collection.md).

2026-11-04: 실제 스킨케어 탭의 1~100위 수집, 앱 버튼을 통한 D1 저장, 랭킹 조회, CSV/XLSX 다운로드를 확인했습니다. 전체 랭킹에서 상품 분류로 필터링한 결과가 아닙니다.

## 사용

`bash ./start-local.sh`로 서버를 시작하고 대시보드의 **수집 카테고리 → 스킨케어 → 지금 수집하고 저장**을 누릅니다. 랭킹/분석/내보내기 화면에서 스킨케어를 선택해 확인합니다. Python 서비스를 이미 실행 중이었다면 서버를 재시작해야 합니다.

이 검증 시점의 버튼 수집 지원은 전체와 스킨케어였습니다. 나머지 카테고리 확장 내용은 최신 문서를 참고하세요.

## 구조와 검증

- Python과 TypeScript는 `src/shared/collectionCategories.json`의 카테고리 이름과 고정 출처 URL을 공유합니다.
- 실제 선택된 탭의 ID와 최종 URL의 카테고리 파라미터가 요청과 일치할 때만 100개 결과를 승인합니다.
- Worker, Python 서비스, 클라이언트에서 카테고리·출처를 검증합니다. 클라이언트는 요청한 카테고리와 다른 결과를 저장하지 않습니다.
- 같은 카테고리의 실행 중 작업은 재사용하고, 다른 카테고리의 동시 요청은 409로 거부합니다.
- 날짜·카테고리별 스냅샷으로 저장하며 전체 랭킹 스냅샷과 분리합니다. 수집 중 오류가 나면 기존 완료 기록을 유지합니다.
- 검증용으로 이 PC에 넣었던 스킨케어 가상 샘플은 이력에 보존하면서 비활성화했습니다. 실제 데이터와 가상 샘플의 순위를 비교하지 않도록 했습니다.
- 실제 100개 순위·ID·브랜드·상품명·URL·상품 대분류를 수집 결과와 DB에서 대조했습니다. 가격은 NULL, 이미지 필드는 제외, 해당 날짜 스킨케어 활성 COMPLETE는 하나입니다.
- 브라우저에서 CSV/XLSX 다운로드와 CSV 100개 ID 일치, 빈 검색 결과에서 내보내기 비활성화를 확인했습니다.
- TypeScript/production build/ESLint 통과. Vitest 79개, Python 서비스 14개 통과.

캡처와 검증 파일은 Git에서 제외한 `data/skincare-button-capture.json`에 있습니다. 대조 명령은 `pnpm verify:capture data/skincare-button-capture.json`입니다. 다른 로컬 앱 포트는 `OLIVERANK_PORT`로 지정할 수 있습니다.

검증은 사용자가 실행한 서버를 종료하지 않고 별도 앱 포트 8791에서 수행했습니다. 같은 작업 사본의 로컬 D1에 저장하므로 기본 앱 포트 8787에서도 기록을 조회할 수 있습니다.
