# 제조사명·판매업자 수집

상품정보 제공고시의 **화장품제조업자,화장품책임판매업자 및 맞춤형화장품판매업자** 항목을 사용합니다.

- 첫 `/` 앞부분을 제조사명에 저장합니다.
- 첫 `/` 뒷부분 전체를 판매업자에 저장합니다. 추가 `/`가 있으면 뒷부분에 그대로 남깁니다.
- 앞뒤 공백은 제거하며 고시 원문도 별도 저장합니다.
- 해당 항목이 없거나 구분자가 없으면 임의로 제조사·판매업자를 추정하지 않습니다.
- 성분 키워드 추출은 [성분 키워드 규칙](ingredient-keywords.md)을 따릅니다.

예: `(주)코스비전/(주)아모레퍼시픽` → 제조사명 `(주)코스비전`, 판매업자 `(주)아모레퍼시픽`.

공개 상품 페이지를 순서대로 방문해 고시를 펼치고 확인합니다. 항목을 찾지 못한 상품은 빈값으로 남기며 접속 확인 화면이나 반복 오류가 나오면 추가 상세 조회를 멈춥니다. 확인된 제조사 정보는 최대 24시간 재사용합니다. 작업 제한은 900초, 앱 대기는 960초입니다.

DB에는 `manufacturer_name_at_capture`, `seller_name_at_capture`, `manufacturer_disclosure_at_capture`를 저장합니다. 기존 버전은 보존하며 새 수집 버전에서 값을 표시합니다. 랭킹 표와 CSV/XLSX에 제조사명·판매업자가 포함됩니다. 필요한 로컬 마이그레이션은 `0007_manufacturer_seller.sql`, `0008_manufacturer_replay_guard.sql`입니다.

검증: TypeScript/프로덕션 빌드, ESLint, Vitest 86개, Python 23개 통과. 첫 구분자·공백·추가 구분자·구분자 없는 원문 처리, DB 저장·변경 청크 재전송 방지, CSV/XLSX 문자열 저장을 확인했습니다.

실제 전체 랭킹 100개를 수집·저장했습니다. 고시 원문 22개를 확인했고 구분자가 있는 20개는 제조사명·판매업자를 분리해 저장했습니다. 이후 접속 확인 화면이 발생해 후속 상세 조회를 중단했습니다. 확인하지 못한 값은 빈칸이며, 다른 카테고리의 활성 스냅샷 ID가 변경되지 않았음을 확인했습니다. 원문·분리값과 DB를 대조해 모두 일치했습니다.

캡처는 `data/overall-manufacturer-capture.json`, 검증은 `data/overall-manufacturer-verification.json`이며 Git에서 제외됩니다. 수집기에서 확인된 원문을 캐시하므로 나중에 수집을 다시 실행할 때 중복 방문을 줄입니다. 접속 제한을 자동으로 재시도하거나 우회하지 않습니다.

이번 제조사 수집에서 리뷰를 다시 확인하지 못해도 기존 정보를 잃지 않도록 같은 날 이전 수집에서 확인한 55개 상품의 리뷰 수·평점을 보존했습니다. 이 값은 제조사 수집 시점에 새로 조회한 값이 아니며, 원래 확인 시각은 `data/overall-manufacturer-review-provenance.json`에 별도로 기록했습니다.
