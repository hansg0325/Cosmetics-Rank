# 상품 대분류 해석 수정

## 원인

카드의 `data-ref-goodscategory`는 `메이크업 > 립메이크업 > 립케어` 대신 `02 > 립 메이크업 > 립케어(컬러립밤)`처럼 상위 그룹을 숫자로 표시합니다. 기존 코드는 숫자를 버리고 첫 이름을 대분류로 사용해 중분류가 표시됐습니다.

## 수정

`scripts/product_taxonomy.py`에서 실제 관측한 그룹을 해석합니다.

| 경로 | 저장할 상품 대분류 |
| --- | --- |
| 02 > 립/아이/베이스 메이크업 > 하위 | 메이크업 |
| 03 > 퍼퓸/홈 프래그런스 > 하위 | 향수/디퓨저 |
| 04 > 바디 보습류/핸드케어 등 > 하위 | 바디케어 |
| 05 > 헤어 트리트먼트/스타일링 등 > 하위 | 헤어케어 |

`01`은 스킨케어·클렌징·선케어·마스크팩을 함께 포함하므로 숫자를 단일 대분류로 치환하지 않고 첫 이름을 유지합니다. 빈 값과 미확인 그룹도 검사합니다.

상품 대분류는 랭킹 출처와 별개입니다. 예를 들어 맨즈에딧 랭킹의 쿠션 상품도 상품 대분류는 메이크업입니다.

## 반영과 검증

기존 스냅샷을 직접 수정하지 않고 전체+9개 카테고리를 수정된 수집기로 재수집해 현재 활성 기록에 반영합니다. 내용이 달라진 기록은 새 버전으로 저장하고 이전 버전을 보존합니다.

Python 서비스 및 분류 테스트 19개 통과. 실제 메이크업 100개 재저장 후 전부 `메이크업`으로 조회되는 것을 확인했습니다.

전체 10개 카테고리 1,000행을 재수집·저장하고 수집 결과와 DB를 대조해 모두 일치했습니다. 실패 0개, 약 154초였습니다. 메이크업 100개는 모두 메이크업, 바디케어 100개는 모두 바디케어로 저장됐습니다. 전체·더모 코스메틱·맨즈에딧에 포함된 메이크업 상품도 같은 규칙으로 수정됐습니다. 상세 검증은 Git에서 제외한 `data/taxonomy-fix-verification.json`에 있습니다.
